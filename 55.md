Выполни полный независимый server2 acceptance для Stage 5G schema prerequisite — migration 017.

```text
Repository:
shamilmirz/paper-trading-engine

Branch:
stage/05-trading-core

Required SHA:
4c961194204be362f8847cb9421c6e2dff6b3d5c
```

Это полный acceptance-запуск, не precondition-only и не diagnostic-only.

Не возвращай промежуточный отчёт после cleanup, checkout или readiness. Выполни весь scope в одном запуске и верни только итоговый `PASS` либо реальный `FAIL`.

## 4. External full harness

Создай временный harness вне репозитория.

Обязательно:

```bash
set -Eeuo pipefail
```

До запуска проверь:

```bash
bash -n run_acceptance.sh
bash -n cleanup.sh
```

Используй явные фазы:

```text
PHASE=BOUNDARY
PHASE=POSTGRES_STARTUP
PHASE=STABLE_READY
PHASE=MIGRATIONS
PHASE=SAFE_ROLE_COLLISION
PHASE=SECURITY_DEFINER_COLLISION
PHASE=OWNER_ACL
PHASE=CURSOR_CONTRACT
PHASE=REGRESSIONS
PHASE=FINAL_INVARIANTS
PHASE=CLEANUP
```

`STABLE_READY=PASS` — только промежуточный этап. После него harness обязан перейти в `PHASE=MIGRATIONS`.

Настрой:

```text
ERR trap:
сначала вывести failed phase, failed command и diagnostics;

EXIT trap:
после diagnostics удалить все acceptance-owned resources.
```

Cleanup не должен запускаться сразу после readiness.

## 6. Stable readiness

Используй уже доказанный bounded startup polling.

Допускаются временные состояния во время normal initdb:

```text
no response
rejecting connections
database system is starting up
database system is shutting down
```

Они не являются FAIL, пока:

```text
container running
RestartCount не меняется
OOMKilled=false
startup timeout не превышен
```

Требуется дождаться завершения official image init process и финального PostgreSQL server.

После этого:

```text
5 последовательных pg_isready successes
интервал минимум 2 секунды
```

Затем внутри контейнера:

```sql
SELECT 1;
SELECT version();
SELECT pg_postmaster_start_time();
```

Через минимум 5 секунд повторить:

```sql
SELECT 1;
SELECT pg_postmaster_start_time();
```

После этого выполнить `SELECT 1` через опубликованный localhost port.

Разрешить переход к migrations только если:

```text

container ID не изменился
RestartCount = 0
Running = true
Restarting = false
OOMKilled = false
internal connection PASS
published-port connection PASS
```

Напечатать:

```text

```

## 8. Safe pre-existing owner collision


## 9. SECURITY DEFINER collision

На другой disposable database:

```text
apply migrations 001–016
create safe NOLOGIN paper_stage5g_cursor_owner
create disposable attacker
create SECURITY DEFINER probe reading paper_accounts
transfer probe ownership to owner-role
grant probe EXECUTE to attacker или PUBLIC
```

До migration probe должна завершаться:

```text

```

Migration 017 должна завершаться:

```text
STAGE5G_CURSOR_OWNER_PREEXISTING_CONFLICT
```

После rollback probe снова должна завершаться:

```text
permission denied for table paper_accounts
```

Дополнительно доказать:

```text
schema_migrations version 17 absent
Stage 5G cursor absent
owner SELECT absent
owner CREATE absent
old SECURITY DEFINER probe не активирован
```

После проверки удалить collision database, attacker и owner-role.
