## Цель

Точечно и только в read-only режиме проверить:

1. Подходят ли существующие двухлетние часовые свечи Binance и Bybit для использования в Paper Trading Engine.
2. Подходят ли canonical минутные свечи, записанные за последние 12 полностью закрытых часов.
3. Совпадает ли час, собранный из 60 минут по алгоритму проекта, с существующей часовой свечой.
4. Совпадают ли выборочные свечи с публичными REST API Binance и Bybit.
5. Может ли текущий код Levels использовать существующие `1h` напрямую.

Ничего не исправлять и не внедрять.

# 6. Выборочная проверка двухлетних 1h

Не проверять содержимое каждой свечи.

Для каждой пары:

```text
exchange × symbol
```

выбрать ровно 12 часовых свечей, равномерно распределённых по доступной истории.

Использовать детерминированный принцип:

```sql
NTILE(12) OVER (ORDER BY hour_open_ts)
```

Из каждого сегмента брать первую свечу.

Ожидаемый объём:

```text
2 биржи × 5 символов × 12 свечей = 120 часовых свечей
```

Для каждой из 120 свечей проверить:

```text
exchange правильный;
symbol правильный;
время timezone-aware и приведено к UTC;
open_ts выровнен на HH:00:00;
close_ts, если хранится, равен open_ts + 1 hour;
open > 0;
high > 0;
low > 0;
close > 0;
low <= open <= high;
low <= close <= high;
volume_base >= 0;
volume_quote не NULL;
volume_quote >= 0;
значения конечные, без NaN и Infinity;
для ключа exchange + symbol + open_ts существует ровно одна строка;
предыдущий или следующий час присутствует, кроме фактической границы листинга.
```

По каждому выбранному ключу отдельно проверить локальные дубли:

```sql
SELECT count(*)
FROM <hourly_relation>
WHERE exchange = :exchange
  AND symbol = :symbol
  AND hour_open_ts = :open_ts;
```

Ожидание:

```text
count = 1
```

Не выполнять глобальное сканирование всех двухлетних строк на дубли.

# 10. Собрать 1h из проверенных минут

Для каждой пары `exchange × symbol` разделить 720 минут на 12 полных UTC-часов.

Применить строго алгоритм проекта:

```text

low          = min(low);
```

```text

все quality_status = COMPLETE;
все is_closed = true;

последняя close_ts не находится в будущем.
```

Получить:

```text

```

```text

переход backfill/live не имеет конфликтов или gaps.
```

Минутные данные можно признать подходящими только если:

```text
по каждой паре имеется 720/720 минут;
нет gaps;
нет duplicates;
все строки closed + COMPLETE;
volume_quote заполнен;
REST-сверка проходит;
12 агрегированных часов корректно собираются.
```

Общий положительный вывод допускается только в форме:

```text
Candles are suitable as source material for Paper Trading Engine.
Current Levels code still does not consume existing historical 1h directly.
A separate canonical 1h adapter or reader integration is required.
Production source remains BLOCKED until that integration is independently accepted.
```
