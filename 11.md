# MONITOR-DATA — PRODUCTION CANDLE SYSTEM REBUILD

## Цель

Полностью подготовить `monitor_data` для проекта `paper-trading-engine`.

После выполнения в production должны остаться два основных источника свечей:

```text
public.candles_1m_canonical
public.candles_1h_canonical
```

Назначение:

```text
candles_1m_canonical
→ Features
→ Scanner
→ Growth
→ Levels minute
→ будущие Detector / Signal
→ Paper Entry / Trade Manager

candles_1h_canonical
→ Growth hourly discovery
→ Levels initial two-year rebuild
→ Levels hourly discovery
```

`5m`, `15m`, `30m` и остальные интервалы отдельно хранить для нового проекта не требуется. Они рассчитываются из canonical `1m` там, где нужны.

# 1. Разрешённые изменения

Разрешено в рамках candle-системы:

```text
изменять monitor-data;
создавать migrations;

выдавать paper_market_reader только SELECT;
перезапускать candle collectors после проверки;
создавать тесты и отчёты.
```

Запрещено:

```text
начинать Stage 5;
удалять старые candle relations до полной проверки новых.
```

# 2. Какие данные требуются

## Canonical 1m

Для каждой биржи:

```text
Binance USDⓈ-M perpetual
Bybit linear USDT perpetual
```

Для всех активных символов проекта:

```text
история: последние 35 полных дней;
live: каждая новая закрытая 1m свеча;
retention: 35 дней;
compression: после 7 дней.
```

Canonical `1m` используется для:

```text
текущей цены;
изменений 5m/15m/30m/2h/24h;
объёмов 3m/15m/24h;
Scanner;
Growth;
касания уровня;
реакции;
пробоя;
ретеста;
входа и управления сделкой.
```

## Canonical 1h

Для каждой биржи и каждого активного символа:

```text
история: последние 2 года;
если монета моложе — от первой доступной свечи;
live: каждый новый полностью закрытый час;
retention: отсутствует;
compression: после 30 дней.
```

Исторические и новые `1h` должны поступать одним способом — напрямую из native `1h` API биржи.

Не смешивать:

```text
historical native 1h
с
live 1h, построенными другим алгоритмом
```

Агрегация `1m → 1h` используется только для контроля native `1h`, а не как основной источник.

# 3. Источники бирж

## Binance

Использовать USDⓈ-M Futures:

```text
GET https://fapi.binance.com/fapi/v1/klines
```

Параметры:

```text
symbol=<SYMBOL>
interval=1m или 1h
startTime=<UTC milliseconds>
endTime=<UTC milliseconds>
limit=<максимально допустимый размер страницы>
```

Mapping:

```text
[0]  open time
[1]  open
[2]  high
[3]  low
[4]  close
[5]  base asset volume
[6]  exchange close time
[7]  quote asset volume
[8]  trade count
```

Сохранять обязательно:

```text
volume_base = [5]
volume_quote = [7]
```

## Bybit

Использовать:

```text
GET https://api.bybit.com/v5/market/kline
category=linear
interval=1 или 60
```

Mapping:

```text
[0] startTime
[1] openPrice
[2] highPrice
[3] lowPrice
[4] closePrice
[5] volume
[6] turnover
```

Для USDT linear:

```text
volume_base = volume
volume_quote = turnover
```

Bybit возвращает до 1000 свечей за запрос и сортирует результат от новых к старым, поэтому перед сохранением данные необходимо привести к хронологическому порядку.

Для Binance и Bybit значения из JSON читать как строки и преобразовывать через `Decimal`. Не преобразовывать через Python `float`. Официальные futures API предоставляют native свечи необходимых интервалов и поля базового и котируемого объёма.

# 4. Финальные таблицы

## public.candles_1m_canonical

Создать TimescaleDB hypertable с колонками:

```text
exchange                text            NOT NULL
symbol                  text            NOT NULL
interval                text            NOT NULL
open_ts                 timestamptz     NOT NULL
close_ts                timestamptz     NOT NULL
open                    numeric(38,18)  NOT NULL
high                    numeric(38,18)  NOT NULL
low                     numeric(38,18)  NOT NULL
close                   numeric(38,18)  NOT NULL
volume_base             numeric(38,18)  NOT NULL
volume_quote            numeric(38,18)  NOT NULL
trade_count             bigint          NULL
is_closed               boolean         NOT NULL
quality_status          text            NOT NULL
source                   text            NOT NULL
source_event_id          text            NOT NULL
source_updated_at        timestamptz     NULL
ingested_at              timestamptz     NOT NULL
checksum                 text            NOT NULL
source_contract_version text            NOT NULL
```

Ограничения:

```text
exchange IN ('binance', 'bybit')
interval = '1m'
close_ts = open_ts + interval '1 minute'
is_closed = true
quality_status = 'COMPLETE'
open_ts выровнен по UTC-минуте
open > 0
high >= open
high >= close
low <= open
low <= close
low > 0
volume_base >= 0
volume_quote >= 0
```

Уникальность:

```text
PRIMARY KEY (exchange, symbol, open_ts)
```

Indexes:

```text
(exchange, open_ts DESC)
(exchange, symbol, open_ts DESC)
(symbol, open_ts DESC)
```

TimescaleDB:

```text
chunk interval: 1 day
compression: after 7 days
retention: after 35 days
segment by: exchange, symbol
order by: open_ts
```

```text

compression: after 30 days

```

Уникальность:

```text

```

# 6. Правила записи

Ключ свечи:

```text
(exchange, symbol, open_ts)
```

Поведение при повторной записи:

```text
ключ отсутствует
→ INSERT

ключ существует и checksum совпадает
→ NO-OP

ключ существует и checksum отличается
→ существующую свечу не перезаписывать
→ сохранить конфликт
→ пометить ingestion run как DEGRADED
```

Создать:

```text
public.candle_conflicts
```

Минимальные поля:

```text
exchange
symbol
interval
open_ts
existing_checksum
incoming_checksum
existing_source
incoming_source
existing_payload
incoming_payload
detected_at
resolved_at
resolution
```

Нельзя молча заменять REST-свечу WebSocket-свечой или наоборот.

# 7. Backfill 1m

Скачать последние 35 полных дней напрямую с каждой биржи.

Граница:

```text
start = UTC now floor minute - 35 days
end = начало текущей открытой минуты
```

Текущую открытую свечу не сохранять.

Порядок:

```text
1. Binance — все активные символы проекта.
2. Bybit — все активные символы проекта.
3. Страницы скачивать последовательно по времени.
4. Каждую страницу сохранять отдельной транзакцией.
5. После страницы фиксировать checkpoint.
6. После ошибки продолжать с последнего checkpoint.
```

Нельзя использовать старую `candles_1m` как основной источник миграции.

Старую таблицу разрешено использовать только для сравнения.

---

# 8. Backfill 1h

Скачать native `1h` за два года напрямую с бирж.

Граница:

```text
start = max(UTC now - 2 years, первая доступная свеча символа)
end = начало текущего открытого часа
```

Для каждого символа скачать:

```text
OHLC
volume_base
volume_quote
trade_count — если биржа его предоставляет
```

Не рассчитывать:

```text
volume_quote = close × volume_base
```

Не копировать данные из старых:

```text
candles_1h
candles_1h_raw
```

Старые таблицы можно использовать только для сравнения OHLC.

# 10. Live 1m

Binance и Bybit WebSocket продолжают принимать `1m`.

В canonical публиковать только закрытую свечу:

```text
Binance: closed flag подтверждён
Bybit: confirm/closed flag подтверждён
```

Текущую формирующуюся свечу в canonical не публиковать.

После reconnect:

```text
REST repair последних 15 минут
```

Периодическая проверка:

```text
каждые 5 минут — последние 30 минут;
каждый час — последние 3 часа;
раз в сутки — все 35 дней по symbol/day chunks.
```

---

# 11. Live 1h

После закрытия каждого UTC-часа:

```text
подождать ingestion grace;
запросить native 1h через REST;
сохранить в candles_1h_canonical;
при ошибке выполнить retries;
не строить production 1h только из 1m.
```

Проверять новый `1h` агрегацией последних 60 canonical `1m`.

Основной источник:

```text
native exchange REST 1h
```

Контрольный источник:

```text
aggregate 60 canonical 1m
```

При расхождении записывать конфликт и не скрывать его.

---

# 12. Gap repair

Для каждой relation проверять ожидаемый календарь:

```text
1m → каждая UTC-минута
1h → каждый UTC-час
```

Проверка выполняется отдельно по:

```text
exchange
symbol
interval
```

Для пропуска:

```text
1. повторный REST-запрос;
2. повторная проверка;
3. INSERT при успешном восстановлении;
4. запись gap/error, если биржа не вернула свечу.
```

Не создавать искусственную пустую свечу.

# 14. Обязательная проверка перед очисткой legacy

## Canonical 1m

Для каждого exchange × symbol:

```text
нет дублей;
нет неожиданных gaps;
все свечи закрыты;
все quality_status=COMPLETE;
нет NULL OHLC;
нет NULL volume_base;
нет NULL volume_quote;
timestamps выровнены;
OHLC логически корректны;
checksum заполнен;
source_event_id заполнен.
```

Ожидаемая глубина:

```text
35 дней
или
от даты листинга, если символ моложе.
```

## Canonical 1h

Проверить:

```text
2 года
или
от даты листинга;
нет дублей;
нет gaps;
volume_quote заполнен;
UTC open timestamp;
полный source contract.
```

## REST-сверка

Символы:

```text
BTCUSDT
ETHUSDT
SOLUSDT
XRPUSDT
DOGEUSDT
```

При отсутствии заменить:

```text
ADAUSDT
LINKUSDT
LTCUSDT
```

Проверить:

```text
последние 12 часов 1m полностью;
12 равномерных 1h за два года;
обе биржи;
OHLC;
volume_base;
volume_quote;
timestamp.
```

## 1m → 1h

За последние 7 полных дней:

```text
собрать каждый час из 60 canonical 1m;
сравнить с native canonical 1h;
вывести все расхождения.
```
