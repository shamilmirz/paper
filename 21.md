# ТЗ агенту: тестовое подключение Paper Trading Engine к серверной Market Data DB

## 1. Роль

Ты отвечаешь за безопасное тестовое подключение проекта:

```text
Repository: shamilmirz/paper-trading-engine
Branch: stage/04c-candle-source-integration
PR: #3
```

Работай как инженер интеграции и критик.

Главное правило:

```text
Сначала построить карту текущей системы и проверить факты.
Только после этого что-либо изменять.
```

Не считай подключение успешным только потому, что контейнер запустился. Нужно доказать, что проект читает правильные свечи, из правильных таблиц, правильной ролью и не может записывать в рыночную базу.

# 9. Проверить содержимое свечей

Проверить отдельно обе таблицы.

## 9.1 Общая статистика

Для каждой таблицы получить:

```text
общее количество строк;
количество строк Binance;
количество строк Bybit;
минимальный open_ts;
максимальный open_ts;
количество символов;
количество COMPLETE;
количество закрытых свечей;
количество NULL volume_quote.
```

Обязательные условия:

```text
- таблица не пустая;
- есть Binance;
- есть Bybit;
- 1m-таблица содержит interval='1m';
- 1h-таблица содержит interval='1h';
- используемые строки имеют is_closed=true;
- quality_status='COMPLETE';
- volume_quote не NULL;
- timestamps находятся в UTC.
```

## 9.2 Проверка дубликатов

Проверить дубликаты по ключу:

```text
exchange + symbol + interval + open_ts
```

В тестовом диапазоне дубликатов быть не должно.

## 9.3 Проверка временных разрывов

На ограниченном диапазоне проверить:

```text
Binance: BTCUSDT и ещё один доступный символ
Bybit: BTCUSDT и ещё один доступный символ
```

Для 1m проверить последние 24–48 часов.

Для 1h проверить доступный диапазон до 21 дня.

Отчёт должен отдельно показать:

```text
ожидаемое количество свечей;
фактическое количество;
количество пропусков;
время первого пропуска.
```

Ничего не исправлять.



```text

- разрешать любую строку;
```

После исправления обновить тесты и документацию конфигурации.
