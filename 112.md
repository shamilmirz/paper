# 5. Сравнить 60 свечей с биржами

Использовать публичные endpoints:

```text

GET /v5/market/kline
category=linear

```

Binance официально предоставляет USDⓈ-M kline endpoint; Bybit возвращает OHLC, base volume и quote turnover.

Сравнить:

```text

```

Правила:

```text
timestamp — точное совпадение;
OHLC — точное Decimal-совпадение либо relative difference <= 1e-12;
volume — relative difference <= 1e-9;

```

При расхождении вывести:


# 6. Главная проверка volume_quote

Levels использует именно `volume_quote` для сравнения объёма свечи с медианой предыдущих 30 часов.

Вернуть один из вердиктов по каждой бирже:

```text
A. STORED_DIRECTLY
В БД уже хранится настоящий quote volume / turnover.

B. STORED_UNDER_WRONG_NAME
Настоящий quote volume хранится, но колонка названа неправильно.

C. DOWNLOADED_BUT_DISCARDED
Биржа отдала quote volume, но backfill его не записал.

D. NEVER_DOWNLOADED
Старый backfill вообще не запросил или не разобрал quote volume.

E. AMBIGUOUS
Семантику доказать невозможно.
```

Запрещено считать:

```text
volume_quote = close × volume_base
```

Это приблизительная оценка, а не реальный торговый оборот свечи.

# 9. Варианты решения

Выбрать один вариант.

## Вариант 1 — использовать существующий backfill

Допустим только если:

```text
OHLC совпадает с биржей;
volume_base доказан;
volume_quote доказан;
timestamp означает начало часа;
данные Binance/Bybit разделены.
```

Вердикт:

```text
REUSE_EXISTING_1H_BACKFILL
```

## Вариант 2 — восстановить потерянное поле

Допустим, если quote volume был сохранён в другой колонке или исходном payload.

Вердикт:

```text
REMAP_EXISTING_1H_BACKFILL
```

## Вариант 3 — повторно скачать 1h

Обязателен, если старый backfill сохранил только OHLC и base volume, а настоящий quote volume потерян.

Вердикт:

```text
REDOWNLOAD_1H_WITH_QUOTE_VOLUME
```

Binance и Bybit способны отдать нужное поле, поэтому отсутствие `volume_quote` в нашей БД не является ограничением бирж.
