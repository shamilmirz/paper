Выполни полный независимый server2 acceptance для Stage 5G schema prerequisite — migration 017.

```text
Repository:
shamilmirz/paper-trading-engine

Branch:
stage/05-trading-core

Required SHA:
4c961194204be362f8847cb9421c6e2dff6b3d5c
```

Предыдущий запуск остановился в `PHASE=STABLE_READY`, потому что на server2 отсутствует host-команда `psql`.

Это ошибка внешнего harness, не PostgreSQL и не repository failure.

## Главное исправление harness

Не устанавливай `psql`, PostgreSQL client packages или другие host-пакеты.

Не выполняй:

```text
apt install
apt-get install
apk add
yum install
изменение host PATH
```

Внутренний PostgreSQL connection по-прежнему проверяй через:

```text
docker exec <postgres-container> psql ...
```

Опубликованный localhost port проверяй отдельным одноразовым PostgreSQL 16.4 client-контейнером через Linux host network.

Пример обязательной проверки:

```bash
external_result="$(
  docker run --rm \
    --label "paper.stage5g.acceptance.client=${RUN_ID}" \
    --network host \
    -e PGPASSWORD="${PGPASSWORD}" \
    postgres:16.4 \
    psql \
      "host=127.0.0.1 port=${PGPORT_PUBLISHED} dbname=${PGDATABASE} user=${PGUSER} sslmode=disable connect_timeout=5" \
      -v ON_ERROR_STOP=1 \
      -Atc "SELECT 1"
)"

test "${external_result}" = "1"
```

Требования:

```text
client image = postgres:16.4
connection host = 127.0.0.1
connection port = фактический случайный published port
database/user/password = disposable acceptance credentials
query result exactly = 1
exit code = 0
client container удаляется через --rm
```

Эта проверка действительно тестирует published localhost port без установки host `psql`.

Если `--network host` неожиданно недоступен, верни infrastructure `FAIL` с точной ошибкой. Не устанавливай пакеты и не заменяй внешний probe внутренним `docker exec`.
